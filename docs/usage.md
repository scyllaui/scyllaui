# ScyllaUI 使用说明（素材）

本文是生成图文使用说明的素材，只写用户看得到的功能与规则；实现细节与协议见设计文档（由维护者保存，不随公开仓库发布）。面向用户的功能有新增或改动时同步更新本文。界面文字按中文界面写，英文界面的对应文字见 `src/app/ScyllaUI/Localizable.xcstrings`。

版本号规则见本文最后一节。

## 1. ScyllaUI 是什么

把多个项目里的 Claude Code、Codex、Kimi Code、Grok Build、OpenCode、GitHub Copilot CLI、Antigravity CLI 和普通 Shell 放进一个原生 macOS 窗口：左侧侧栏按项目列出所有终端和它们的实时状态，右侧是完整的原生终端。退出 App 后终端和其中的 AI 继续运行，重开即可接回。

## 2. 打开与版本

- 安装（0.4.30 起）：只支持 Apple 芯片的 Mac，系统需要 macOS 14（Sonoma）及以上；更低的系统打不开。打开下载的 `ScyllaUI-<版本>.dmg`，把窗口里的 ScyllaUI 拖到旁边的「应用程序」，再从「应用程序」或程序坞打开。安装包经 Apple 公证，第一次打开时系统只问一次「ScyllaUI 是从互联网下载的 App，确定要打开吗？」（写明 Apple 已检查、未发现恶意软件），点「打开」即可。直接在 DMG 窗口里双击打开时，ScyllaUI 先提示「请先把 ScyllaUI 拖到『应用程序』」：点「退出」后照做，或点「仍然打开」临时使用（从 DMG 运行时后台也在 DMG 里，推出 DMG 后终端会断）。升级时把新版拖进去、选「替换」，下次打开 ScyllaUI 时后台原地换成新版本，终端不断。
- 从程序坞或 Finder 打开正式版 `ScyllaUI.app`。不要在某个 AI CLI 的会话里用 `open` 打开：那样会把该 CLI 的环境变量带进 ScyllaUI 的所有终端。
- **检查更新**（M4b 块 3）：菜单「ScyllaUI › 检查更新…」随时可点；有新版时弹窗列出版本，点「安装更新」后 ScyllaUI 下载、校验签名、替换自己并重新打开，终端和其中的 Agent 不断，后台原地换成新版本。第一次打开不联网；第二次打开时询问「要自动检查更新吗？」，同意后每天检查一次，有新版时同样弹窗，由您决定装不装（不会自动安装）。选了「不检查」也可以随时点「检查更新…」，或在「设置 › 关于」里打开「自动检查更新」，或自己下载新的 DMG 拖进「应用程序」替换。检查更新是 ScyllaUI 唯一的网络请求，只带 App 名称和版本号。从 DMG 或临时位置直接打开时不检查更新（那里替换不了）。ScyllaUI 由别的账户（如管理员）装在「应用程序」里、当前账户没有权限替换它时，安装更新会弹出系统的授权框，第一句是英文「ScyllaUI wants permission to update.」（这句由更新组件写死、不翻译），请管理员输入名称和密码；点「取消」则不安装，ScyllaUI 弹「没有安装更新」说明原因，之后可再点「检查更新…」重试。
- 菜单「ScyllaUI › 关于 ScyllaUI」：显示 App 图标与「版本 <版本号>（构建号 · 构建标识）」。
- 界面语言默认跟随系统（中文、英文）；可在「设置 › 语言」里改为简体中文或 English，重启 ScyllaUI 后生效（提示框里可「立即重启」，终端和其中的 AI 不受影响）。
- 使用须知（2026-11-07 起，取代 2026-11-02 的《最终用户许可协议》）：ScyllaUI 开源，按 GPL-3.0-or-later 发布，使用不需要同意任何协议。第一次打开（以及须知改版后）开屏之后先是一页《使用须知》，全文可滚动，按界面语言显示中文或英文，写明开源许可、不提供担保、第三方 CLI 与 Agent 的行为由用户决定、ScyllaUI 对 CLI 配置的修改、隐私与名称标志。只有「继续 →」，关掉欢迎窗口也不会退出 ScyllaUI。显示过当前版本后不再出现，随时可在「设置 › 关于 › 使用须知…」查看。
- 品牌：App 图标为纯黑底、亮白单龙头，口中是终端提示符 `>_`；开屏是冰蓝色六首龙，浅色开屏用细轮廓，暗黑开屏弱化轮廓，六头沿颈部弯曲，播完回到完整静止图形。
- 开屏页（0.4 起）：每次打开 ScyllaUI 都显示，主窗口上会盖一层与它同大的欢迎窗口，Scylla 的六个头扭动几下、字标拼合，约 5 秒。字标下方是像素字副标题「Keep agents in sight」与像素按钮「开始使用 →」，底部居中一行是版本号与版权声明「Copyright © 2026 Siyuan Zhang. All rights reserved.」（2026-10-30 起；「关于 ScyllaUI」面板也显示这句版权）。点一下或按 Esc、空格、回车可跳过；不受系统「减少动态效果」设置影响。点「开始使用 →」进入 ScyllaUI，期间主窗口照常接回终端。按住欢迎窗口顶部可以拖动，主窗口跟着一起移动（2026-10-28 起）。
- 首次打开（以及主或次版本号变化，如 0.3 → 0.4）时，开屏后接三页引导（0.4.1 起，原为两页）：① 「文稿」「桌面」「下载」等文件夹的访问授权：系统询问时请选「允许」，否则在这些文件夹里运行的终端和 AI 会卡住；② 「让侧栏知道每个 Agent 在干什么」：左右两张卡片用侧栏样例对比装与不装状态同步（Hook）的区别（七款样例，装上之后显示 Running、需确认、待查看、已结束（Stopped，「最近任务」里的样子）、Error、已看过的 Ready 与提示词，有通知和角标；不装七款都是「未知」并标「未同步」，没有通知，「最近任务」为空），下方列出装上能得到的四样；③ 「安装状态同步」：三条说明（只在 ScyllaUI 的终端里起作用、先列出改动再写入并备份、随时可撤销）、四款 CLI 的状态，装了 Codex 且还没正常时多一行带橙色警示符号的提醒（装好后要在 Codex 里输入 `/hooks` 信任）；有要装的时右下角为「以后再说」与「查看改动并安装…」（回车即后者），都已正常时只有「完成」。之后可在「设置 › Agent」逐款撤销（第 9 节）。②③ 左下角有「← 上一步」，可以回看前一页（2026-10-28 起）；窗口越大，引导页整页（文字、图标、按钮）按比例放大，最多 1.5 倍，内容约占窗口宽的六成，③ 的配置文件路径尽量显示全；窗口矮、放不下一页时整页缩小，最低 0.7 倍。关掉欢迎窗口（任何方式）即算看过；首次打开时通知授权的系统询问在欢迎窗口关闭后才出现。
- 最后一页「遇到问题，告诉我们」（2026-11-02 起）：每天第一次打开 ScyllaUI 时出现，不分新老用户，当天再打开（即使中间退出过后台）不再出现，第二天第一次打开又出现。它列出欢迎报告的几种情况（侧栏状态不对、终端显示错乱或卡住、闪退、用着别扭或想要的功能），以及怎么报告：「帮助 › 报告问题…」、写清发生了什么和大约几点、先看诊断包、用邮件或 GitHub 发出（第 13 节）。和引导页一起出现时接在「安装状态同步」之后，那一页的「以后再说」「继续 →」翻到这一页，这一页有「← 上一步」；只出现这一页时，开屏点「开始使用 →」后直接到这里。点「完成」或关掉窗口都算看过。
- 这几页什么时候算「看过」：您在那一页点了「继续 →」「完成」或「以后再说」才算。只是停在某一页、直接关掉欢迎窗口，或者这时退出、改语言让 ScyllaUI 重启，都不算看过，下次打开还会出现。三页引导是一组，在最后一页点了按钮才算看完。
- 第一次打开时主窗口约 1100 × 700、居中；之后记住您调整过的大小与位置。

## 3. 窗口布局

- **左侧侧栏**：顶部居中为 `>_ ScyllaUI` 伪像素斜体品牌字标（0.3.5 起字形加高），带右下阶梯阴影，随侧栏主题自动切换日间蓝与暗黑橙；字标下方一行像素字：版本号在左、副标题「Keep agents in sight」在右（0.4.2 起有副标题与版本号，2026-10-30 起改为像素字、同一行）；再往下是搜索框与「只看待处理」按钮，以及「当前任务」和「最近任务」两区（0.3.5 起分区标题的数字后有一条细分隔线）。默认 300 点宽度可完整显示字标，正式版与测试版共用资源。拖动侧栏右侧的分隔线可拉宽到 420 点，双击分隔线回到 300 点；缩放窗口时侧栏宽度不变，只有终端变宽变窄（0.3.5 起）。
- 暗黑字标使用暖棕橙硬边阴影，使右下像素拖尾更容易辨认；日间字标保持蓝色及原有阴影。
- **右侧终端**：当前选中的终端，直接接在窗口标题栏下方（0.3.5 起去掉了终端上方的窄标题栏；当前是哪款工具看侧栏选中的那一行）。
- **分栏宽度**（0.4.28 起）：侧栏与终端之间、终端与提示词足迹之间的分隔线，鼠标停上去稍等一下会亮起一条蓝线，按住拖动可改宽度（拖动时一直亮着），双击回到默认宽度。窗口铺满屏幕（双击标题栏、绿色按钮或「窗口」菜单的缩放、填充与全屏）时，侧栏与足迹栏照 Claude 桌面版铺满时的三栏重新排宽：侧栏 300，足迹栏占「窗口宽度减去侧栏」的 34.2%（1512 点宽的屏幕约 414，1280 点宽约 335），仍不超出两栏各自的最小、最大宽度；拖边框改窗口大小时不动。
- **标题栏状态行**（窗口最上方）：左边紧跟侧栏开关分三组，CPU 与内存在最右边（0.3.5 起）：
  - 项目与 Git：`[项目名] (分支* +新增 -删除 ?未跟踪)`，`*` 表示有未提交改动，`+N` 绿、`-M` 红；项目名与侧栏一样为绿色（0.4.26 起）。改动数统计的是这个仓库所有未提交的改动（与 `git diff HEAD --numstat` 的行数之和、`git status` 里未跟踪文件数一致），不只是这个终端里的 Agent 改的；
  - 用量：`Total: 累计 token（数值为绿色，0.4.26 起） • 5h: 5 小时额度已用 % (距重置时间) • 7d: 周额度已用 % (距重置时间) • Month: 月额度已用 % (距重置时间)`，百分比低于 50% 绿、50%—80% 黄、80% 以上红。规则对每款都一样（2026-11-01 起）：账号有哪个窗口就显示哪个，没有或不限制的不显示（如部分 Codex 套餐没有 5 小时限制，就只有 `7d`）；这个会话按量计费（Codex、Kimi 接了第三方服务商，Copilot 用自带 key 的模型，OpenCode 有花费）时只显示 `API`。各款来源：Claude（需装 statusline 桥）与 Codex 读会话记录，显示 5h 与 7d（Claude 同时开着几个会话时，以最新一期、用量最高的为准，闲置会话发来的旧数据不会让 5h 消失或回落，0.4.27 起）；Copilot 读它的会话记录，显示月额度（免费账号按每月对话次数，付费账号按高级请求数，2026-11-01 起）；Antigravity、Kimi、Grok 在每轮结束后由后台另起它们自己的命令查询（最多 5 分钟一次，2026-11-01 起）：Antigravity 按您当前所用模型的那一组显示 7 天额度，Kimi 显示 5 小时与 7 天，Grok 显示本期（本机为每周）额度（按当前登录的 grok.com 账号，没登录时悬停写明）；三款在 Agent 一启动时就会查一次；OpenCode 接各家服务商、没有统一的额度，ScyllaUI 暂不读取；
  - 模型：`Model: 模型 (推理强度)`，推理强度是 CLI 自己记录的原文（如 `high`、`xhigh`、`max`，0.3.5 起），四款 CLI 都从各自的会话记录里读，一轮答完后更新；
  - 最右边：`CPU: % • Mem: 内存`，统计的是这个终端的 Shell 及其所有子进程。窗口变窄时右边保持完整，左边先把项目名截在中间（最少 12 个字符）、再截分支（最少 8 个），还放不下依次去掉重置倒计时、推理强度、改动数、Total、模型，腾出来的空间再还给分支和项目名；项目名与额度百分比留到最后。
  - 鼠标悬停在哪一段就说那一段（2026-11-01 起）：项目名显示完整路径，被截的分支显示全名，额度显示重置的具体时间，`API` 说明按量计费；读不到的说明挂在相关的段上（如 Total 上写「额度：ScyllaUI 暂不读取 OpenCode 的额度」，模型上写读不到推理强度）。Total、模型读不到时显示 `-`。
  - 每一段都可以在「设置 › 状态栏」里关掉（项目名、分支与改动、Total、5h 额度、7d 周额度、月额度、按量计费（API）、模型、推理强度、CPU、内存），即时生效，「恢复默认」全部打开。CPU 与内存都关掉后不再统计，分支与改动关掉后不再读取改动数。
- **侧栏开关**：红黄绿按钮右边的按钮，或 `Cmd+\`。

## 4. 侧栏

### 当前任务

- 此刻开着的每个终端一行，按项目分组（同一个 Git 仓库算一个项目，项目行显示分支名；0.4.2 起项目名为绿色，不再显示任务数，任务行之间更紧凑）。
- 每行显示工具图标、工具名与状态：Ready（就绪）、Running（运行中，转圈）、需确认（待审批）、出错（这一轮失败，如额度用完、请求出错；一直显示到您再次提问，0.4.13 起不会在约 1 分钟后自己变回 Ready）、未知（已识别是哪款 AI，但还没收到它的状态事件）；纯 Shell 显示「Shell」，跑普通命令时显示「运行命令」。ScyllaUI 按 AI 程序的安装位置认出是哪一款，认得的安装方式：Claude Code 官方安装脚本与 npm，Codex 官方独立安装包与 npm，Kimi Code、Grok、Antigravity 官方安装脚本，OpenCode 官方安装脚本与 npm，Copilot 官方安装脚本与 npm（0.4.37 起认官方脚本装的 Claude Code、OpenCode、Copilot）；Homebrew 安装、npm 安装的 Kimi Code 暂不支持，运行时这一行显示「运行命令」。改过名的终端在工具名的位置显示您起的名字（0.4.3 起，原来显示在副标题），是哪款 AI 看图标。
- 两个徽标可同时出现：
  - **需确认**：AI 在等您审批，或弹出选项框向您提问（OpenCode、Copilot、Antigravity，Grok 0.4.26 起），处理后自动消失；
  - **待查看**：AI 答完一轮时您没在看这个终端，打开该终端即消失。
- 副标题是您最新的一条提示词（还没提问时为「新会话 · …」；Claude 子代理交回的结果、后台任务完成通知不算，0.4.26 起）；纯 Shell 显示所在目录，写成相对项目的样子：在项目根显示项目文件夹名，在子目录显示「项目/子目录」，主目录下用「~」（0.4.3 起），过长时省略开头、保留末段。
- 悬停（2026-10-30 起）：鼠标停在副标题或名称上，文字被截断时显示全文：提示词保留原来的换行，目录为完整路径；完整显示的不弹提示。ScyllaUI 只存提示词的前 400 字（2026-10-31 前为 200 字，之前存下的不变），超出部分悬停里也没有。原来整行悬停列出的目录、前台进程、会话 ID、CLI 版本不再显示：会话 ID 在提示词足迹的栏头，版本与状态异常的原因在侧栏提示栏的「详情…」里。
- **冲突**：同一段对话同时开在两个终端时，两行第 2 行的时间左侧都标「冲突」，鼠标停上去写明开在几个终端。
- **未同步**（M4b 块 5 起，琥珀色，与「需确认」同一处）：这个终端前台正在跑的 AI，状态同步此刻没生效（缺少条目、已停用，或 Codex 待信任），侧栏看不到它在做什么。点它直接处理：Codex 待信任时去这个终端里的 Codex 打开 `/hooks`（见第 9 节「怎么用」），其余打开这款工具的修复确认框。在「设置 › Agent」撤销过的工具不显示。
- **目录无权限**（0.3.5 起显示在终端行时间左侧，原在终端上方的窄标题栏）：后台进不了这个终端的启动目录（多半是没有文件访问权限），Shell 已在其他目录启动、没有代输启动命令。悬停可看处理方法：在「系统设置 › 隐私与安全性 › 文件与文件夹」中允许 ScyllaUI 访问，再新开终端。
- **目录不存在**（2026-11-13 起与「目录无权限」分开，同一位置）：这个终端的启动目录已不存在（被删除、改名或移走），Shell 已在主目录打开、没有代输启动命令。目录还在别处时，在那里新开终端。
- **置顶项目**（0.3.5 起，0.4.2 起改为悬停按钮）：鼠标停在「当前任务」里的项目行上，右端出现书签按钮，点它置顶，这个项目组排到最前；多个置顶的项目之间、其余项目之间仍按原来的顺序，组内终端顺序不变。置顶的项目行常显实心书签，再点一下即取消。`Cmd+1…9` 与上下键按侧栏顺序走，置顶后编号随之变化。置顶记在 ScyllaUI 的库里，退出、重开都保持；「最近任务」里的项目不能置顶。

### 最近任务

- 已结束、可以恢复的 AI 对话；显示近 14 天内结束的、最多 20 条。
- ScyllaUI 自己的库里默认保留最近 30 天、最多 200 条，超出的自动清理，可在「设置 › 数据」里修改（第 10 节）；CLI 自己的会话记录不受影响。
- 单击一条只选中它；双击才恢复（0.4.2 起，原来单击即恢复，容易误点）：ScyllaUI 在它原来的启动目录新开一个终端，并替您输入恢复命令（命令在终端里可见）；如果这段对话已经在某个终端里运行，直接切过去。恢复失败时会说明原因（会话记录或目录已不存在），可以接着删除这条记录。
- 鼠标停在一条上时，右端出现删除按钮（垃圾桶），点按后确认即删除记录，见第 6 节。
- 副标题是最后一条 AI 回复，鼠标停上去、被截断时显示全文（ScyllaUI 只存前 400 字）。OpenCode、Copilot 的回复 2026-10-31 起也能读到（之前副标题显示任务标题，悬停写明「ScyllaUI 暂不读取 … 的回复」）。

### 提示词足迹（0.4.3 起）

- 菜单「终端 › 提示词足迹」（`Cmd+Y`）在终端右侧打开一栏，标题前是绿色的历史图标；再按一次或点右上角的关闭按钮收起。
- 标题下面两行写明读的是哪段对话：工具名（Claude Code / Codex / Kimi Code / Grok Build / OpenCode / GitHub Copilot CLI / Antigravity CLI）· 当前会话或已结束，再下一行是完整的会话 ID（栏窄时中间省略，鼠标停上去看全文）。
- 列的是当前终端绑定的那段 AI 对话；在「最近任务」里单击选中一条，就换成那段已结束的对话。没有可读的对话时按场景说明（2026-10-30 起）：纯 Shell 写「当前是 Shell，在这个终端启动 Agent 后，这里显示它的历史提示词。」；AI 已在运行、还没收到这次会话的事件（Codex、Kimi 首次提问前，恢复的 OpenCode、Copilot 发第一条之前）写「还没对上 … 的这次会话，发出一条提示词后显示。」，这款的状态同步没生效时改为提示点「未同步」修复；前台是 ScyllaUI 不认识的命令（如 Antigravity 的 `agy`）写「前台运行的 agy 不是 ScyllaUI 已接入的 Agent，没有提示词足迹。」。
- 最新的在最上面，编号 1、2、3…（最早的是 1），左边是和侧栏一样的细连线。每条默认最多显示两行，超出的在编号旁有箭头，点开看全文、再点收起。右边是拷贝按钮和时间（今天 / 昨天 `HH:mm`，今年为日期加时间，更早只显示日期）。
- 鼠标停在一条上，或单击选中一条，时间的位置换成「填入当前终端」：填入与粘贴相同，只放进输入行，不替您回车。选中后按 `Cmd+C` 也能拷贝，双击即填入当前终端。
- 顶部的「筛选」按文字筛选，标题旁的数字变成「符合 / 全部」。
- 拖动这一栏的左边缘可以调宽窄（280—520），双击左边缘回到默认宽度；宽度会记住。
- 内容是 ScyllaUI 按需从 CLI 自己的会话记录读出来的，不存进 ScyllaUI 的库；常见密钥写法显示为 `[REDACTED]`。经「最近任务」恢复过、换了会话的，按会话分段（「以下为恢复前的会话 · 会话 ID」）；会话记录已被 CLI 清理时说明读不到；刚开的对话还没提问时写「这段对话还没有提示词」（0.4.31 起，原先误写成记录已不在）。
- 只列您输入的提示词：工具结果、CLI 自己注入的说明（如 Codex 的 AGENTS.md、环境信息、`/goal` 续跑时的内部提示）不算。几种写法按您输入时的样子显示：Claude 的斜杠命令为 `/命令 参数`；Codex 用 `/goal` 设定的目标为 `/goal 目标`；输入行里的 Shell 命令（Kimi、Grok 的 `!ls`）为 `!ls`；Codex 里粘贴的图片显示为 `[Image #1]`，引用文件、选中回复批注时只显示您的请求，回答 Codex 的提问时显示您的回答。Copilot 的足迹读它自己的会话记录（2026-10-30 起），输入行里的 `!命令` 暂不列（Copilot 其实记在会话记录里，ScyllaUI 还没读这一类记录）。OpenCode 的足迹读它自己的数据库（2026-10-30 起；OpenCode 2 起读它的新表，旧会话照常），输入行的 `!命令` 同样显示为 `!命令`；OpenCode 升级后数据库格式变了读不出时，足迹栏写明读取失败。OpenCode、Copilot 的最后一条回复、token 用量（Copilot 还有模型）2026-10-31 起读它们自己的记录，和其余几款一样显示在「最近任务」与标题栏；周额度没有的，标题栏左侧的悬停写明原因（Copilot 的额度按月计，没有 7 天窗口）。

### 搜索与筛选

- `Cmd+F` 进入搜索框，按子串匹配终端名、任务标题、提示词、最后回复、目录和项目名，同时搜当前任务和已结束的任务（搜索结果最多显示 50 条）。
- 回车打开第一条；在搜索结果里双击已结束的任务即恢复它。两种打开方式都会清空搜索框，侧栏回到原样，新终端直接可见（双击清空自 0.4.13 起）。
- 「只看待处理」：只留下「需确认」或「待查看」的终端。正在显示的终端被筛出列表（比如批准后又在运行中）时，右侧照常显示它，窗口标题、标题栏的模型与额度、提示词足迹也仍按它显示；搜索时同样如此。

菜单「帮助」（2026-11-02 起）：只有「报告问题…」，见第 13 节；顶部的搜索框是 macOS 自带的菜单搜索。

新建的都是 Shell（0.4.2 起不再有「新建 Claude / Codex / Kimi / Grok」）：在终端里输入 `claude`、`codex`、`kimi`、`grok`（或 `agent`，Grok Build 安装器装的同一个程序）、`opencode`、`copilot`、`agy` 启动 AI，自己的参数和别名照常可用。Codex 也直接输入 `codex`（M4b 块 5 起；之前要输入 `codex --no-daemon`）：ScyllaUI 的终端里 `codex` 会自动带上 `--no-daemon`，让 Codex 不连共享后台（ChatGPT 桌面版等在 ScyllaUI 以外启动的那个）、在这个终端里自己运行，侧栏才能收到它的状态。代价是这些 Codex 会话不出现在 ChatGPT 的远程控制与 `codex agents` 列表里。`codex agents`、`codex queue` 这类必须用共享后台的命令原样运行；想让交互界面也连共享后台，输入 `command codex`（此时状态可能显示「未知」）。您自己定义了 `codex` 别名或函数时以您的为准。只在 zsh 里生效；在终端里另起的 `zsh`、`exec zsh` 和 tmux 里没有，需要时手动加 `--no-daemon`。

OpenCode 2（2026-10-31 起支持，实测 2.2.4）：默认所有终端共用一个 OpenCode 后台，ScyllaUI 分不清事件来自哪个终端，所以 ScyllaUI 的终端里输入 `opencode` 时会自动带上 `--standalone`（这个终端单独起一个 OpenCode 服务），侧栏才能显示它的状态；`opencode run`、`opencode mini` 同样，其余子命令（如 `opencode service`、`opencode upgrade`）原样运行。代价是这些会话不在共享后台里，OpenCode 桌面版或网页（`opencode pair`）看不到它们；想连共享后台，输入 `command opencode`（此时状态可能显示「未知」）。从 OpenCode 1 升级后，ScyllaUI 的插件要更新：「设置 › Agent」里 OpenCode 一行显示「缺少条目」时点「修复…」。只在 zsh 里生效。

## 6. 行上的操作

侧栏没有右键菜单（0.4.2 起），操作都在菜单栏（第 5 节）和行上：

- **项目行**：单击折叠或展开；「当前任务」里的项目行悬停时右端出现置顶按钮（第 4 节）。
- **终端行**（当前任务）：第 1 行是这段对话的任务标题（Agent 自己生成的标题，没有时为第一条提示词；还没提问时为工具名，工具看图标），放不下时直接裁掉、侧栏拉宽就多显示，鼠标停上去看全文；第 2 行是最新一条提示词（Kimi、Copilot 的标题就是第一条提示词，问第一句后两行相同，第二句起不同）。单击切换；双击第 1 行改名（输入框里是当前的标题，回车确认、Esc 取消，留空恢复自动）；关闭用 `Cmd+W`。
- **任务行**（最近任务、搜索结果中已结束的任务）：第 1 行同样是任务标题，第 2 行是最后一条回复。单击选中，双击恢复；鼠标停在行上时右端出现删除按钮。
- **删除记录**：点删除按钮，确认后立即从 ScyllaUI 的库里删除这条任务的标题、提示词、回复摘要和事件记录，库文件里也不留原文，无法在 ScyllaUI 中恢复；最近任务的条数随之减少。只针对 ScyllaUI 自己的库，CLI 自己的会话记录不受影响：只要 CLI 还保留着，知道会话 ID 就能在 CLI 里恢复。

## 7. 保活：退出 App 与停止后台

- **退出 App**（`Cmd+Q` 或关窗口）：不弹确认。所有终端和其中的 AI 继续在后台进程 `scyllauid` 里运行，AI 答完一轮、进入审批都照常记录；重开 ScyllaUI 后接回，画面、状态（含「待查看」「需确认」）与退出前一致，可以直接处理退出期间出现的审批。
- **结束后台**：先退出 App。macOS 27 及以后在程序坞右键选「Stop Running in Background」（退出 App 后才出现）；更早的系统没有这一项，在终端里运行 `/Applications/ScyllaUI.app/Contents/Helpers/scyllaui ctl shutdown --force`（App 开着时它会拒绝；不带 `--force` 时，还有终端开着就不结束）。两种做法效果相同：结束后台进程，所有终端和其中的 AI 立刻结束（正在输出的内容中断）；下次打开 ScyllaUI 时，这些对话进「最近任务」，可双击恢复。想彻底停掉时再用，最好先让 AI 答完或在终端里 `exit`。0.4.3 起「设置 › 数据 › 启动时恢复上次的终端」开着时（默认），下次打开会把这些终端开回原来的目录、接着恢复原来跑着的 AI 对话，见下一条；不想恢复，先关掉这个开关，或先在终端里 `exit`。
- **重启电脑或后台被结束后恢复终端**（0.4.3 起，默认开）：下次打开 ScyllaUI 时逐个重建上次的终端：原来跑着 AI 对话的，在对话的启动目录新开终端、替您输入恢复命令；纯 Shell 开回断电前所在的目录（目录不在了退回启动目录，再退回主目录，这时侧栏在这个终端上标「目录不存在」，您 `cd` 到别的目录后消失）。恢复不了的对话（如会话记录已被 CLI 清理）改为在原目录开 Shell。原来前台跑着 AI、却没有能恢复的对话的终端（M4b 块 5 起）恢复为 Shell，并说明原因：这款 AI 的状态同步当时没生效时，弹出「有终端没能接回 Agent」，写明是哪款、为什么，附「修复…」；状态同步正常、只是那个 AI 还没开始对话（如 Codex、Kimi 首次提问前）时不单独提示，只在同一个提示里附一行「还没开始对话」。连续两次恢复到一半 App 就退出时，下次不再自动恢复，改为询问「现在恢复 / 不恢复」。恢复完回到断电前您在看的那个终端。退出 App 不影响终端，不需要恢复。重启电脑时系统会先结束终端里的 AI，ScyllaUI 会把这段对话照样接回；您自己退出 AI 后约半分钟内就重启的，那段对话也会被接回。
- **结束单个终端**：`Cmd+W`、菜单「关闭终端」，或在 Shell 里输入 `exit`。
- **升级 ScyllaUI**：换新版本后重开，后台原地换成新版本，终端不中断，各 AI 的状态（含「需确认」「待查看」）保持不变（0.4.41 起；从 0.4.40 及更早版本升上来的那一次，状态先显示「未知」，等下一个事件更新）。

## 8. 通知与 Dock 角标

- AI 进入「需确认」且您没在看那个终端时，发一条系统通知「<工具> 需确认」，正文为「项目 · 终端名或任务标题」，不含待审批的命令。点通知把 ScyllaUI 调到前台。
- 完成一轮通知（M4a 起，默认关闭）：AI 答完一轮而您没在看那个终端时（即出现「待查看」），发一条「<工具> 已完成」（出错结束时为「<工具> 出错」）；切到那个终端或在其中再次提问即撤回。
- Dock 角标的数字等于侧栏上「需确认」的终端数，为 0 时消失。
- 以上三项在「设置 › 通知」里各有开关：需确认时通知（默认开）、完成一轮时通知（默认关）、Dock 角标（默认开），即时生效。页内显示系统的通知授权状态，被关掉时可点「打开系统通知设置…」。
- 第一次启动时系统会询问通知与角标授权；拒绝不影响侧栏。

## 9. 状态同步（Hook）

### 它是什么

- Claude Code、Codex、Kimi Code、Grok Build 都有官方的 Hook 机制：在会话开始、提交提示词、需要审批、调用工具、一轮结束、会话结束这些时刻，执行配置文件里登记的命令。ScyllaUI 在四款 CLI 的配置文件里各登记几条命令，CLI 运行时由它们把事件告诉 ScyllaUI，侧栏据此更新。ScyllaUI 不读屏幕上的文字判断状态，CLI 改界面不影响它。OpenCode 没有这种命令式 Hook，只有插件：ScyllaUI 在 `~/.config/opencode/plugins/` 放一个自己生成的插件文件 `scyllaui.js`，OpenCode 启动时自动加载，由它把事件转给 ScyllaUI；它只在 ScyllaUI 的终端里起作用，在别处运行 OpenCode 时什么也不做。没装 OpenCode（没有 `~/.config/opencode`）时 ScyllaUI 不建这个目录。GitHub Copilot CLI 的 Hook 是 ScyllaUI 自建的 `~/.copilot/hooks/scyllaui.json`；没装 Copilot（没有 `~/.copilot`）时同样不建。Copilot 同意审批、拒绝审批和按 Esc 中断时不发 Hook，ScyllaUI 从它的会话记录 `~/.copilot/session-state/<会话 ID>/events.jsonl` 里认出这三件事，侧栏随之更新。Antigravity CLI（命令 `agy`）的 Hook 在 `~/.gemini/config/hooks.json`，这份文件 Antigravity 的桌面 App、IDE 与 CLI 共用：ScyllaUI 只增删其中名为「scyllaui」的一项，您自己的 Hook 原样保留；这几条在 App、IDE 和 ScyllaUI 之外的终端里什么也不做。没装 Antigravity CLI（没有 `~/.gemini/antigravity-cli`）时不建。Antigravity 等待审批、拒绝审批和按 Esc 中断时都不发 Hook，ScyllaUI 从它的对话库 `~/.gemini/antigravity-cli/conversations/<对话 ID>.db` 里只读认出，侧栏随之显示「需确认」、回到运行中或 Ready。
- 这些命令只在 ScyllaUI 的终端里起作用：在其他终端（系统「终端」、iTerm 等）里运行的 CLI 执行到它们时什么也不做。
- 写入的位置固定为家目录下各 CLI 的默认配置：`~/.claude/settings.json`、`~/.codex/hooks.json`、`~/.kimi-code/config.toml`（ScyllaUI 的条目写在 `# >>> scyllaui hooks >>>` 标记块内；Kimi 登录、登出时会去掉文件里的注释，标记也随之消失，ScyllaUI 仍能认出并撤销自己的条目；如果您把 Kimi 的 hooks 手写成了行内数组 `hooks = [ … ]`，暂不支持，ScyllaUI 会提示并且不改这个文件，改成 `[[hooks]]` 写法后即可修复）、`~/.grok/hooks/scyllaui.json`、`~/.config/opencode/plugins/scyllaui.js`（整个文件由 ScyllaUI 生成，修复时整份重写，撤销时删除）、`~/.copilot/hooks/scyllaui.json`（同样整份生成）、`~/.gemini/config/hooks.json` 里的「scyllaui」一项（改写前备份；撤销后文件里什么也不剩时删除）。用 `CLAUDE_CONFIG_DIR`、`CODEX_HOME` 等环境变量把配置放到别处的，ScyllaUI 目前看不到也改不到。

### 哪些功能依赖它

- 侧栏的状态（Running、Ready、需确认、出错）与「需确认」「待查看」两个徽标；
- 「需确认」「已完成」系统通知与 Dock 角标（第 8 节）；
- 侧栏副标题里的提示词与任务标题；
- 「最近任务」：对话记录和恢复用的会话 ID 都来自 Hook。
- 某款 CLI 的状态同步未生效时，它的终端照常可用，侧栏仍能认出是哪款工具，但状态显示「未知」，以上几项对它都不起作用，它的对话也不会进入「最近任务」。

### 「设置 › Agent」

- 四款 CLI 每款一行，铺满窗口宽度，从左到右：工具图标与名称（下一行小字为版本与「已验证 / 未验证」）、状态（下一行小字为配置文件位置，放不下时中间省略，悬停看完整路径）、按钮。在别处改了配置文件时，这一页与侧栏提示随之更新。
- 版本（M4b 块 6 起）：这款 CLI 正在终端里运行时显示运行中的版本，没在运行时显示最近一次对话时的版本，都没有时不显示，悬停说明是哪一种。「已验证」表示 ScyllaUI 用这个版本测过状态同步；未验证的新版本通常也能正常使用，侧栏不再为此提示（只在 Hook 数据真有异常时提示「状态可能不准」，见下文「其他入口」）。
- 状态与按钮：

  | 状态 | 含义 | 按钮 |
  |---|---|---|
  | 正常 | ScyllaUI 的条目都在、写法是最新的、没被停用 | 撤销… |
  | 缺少条目 | 部分或全部条目不在了：CLI 升级或重装覆盖了配置、手动编辑时删掉等 | 修复… |
  | 条目需要更新 | 条目都在，但不是当前的写法，或同一条出现了两次（比如旧版本 ScyllaUI 写入的） | 修复… |
  | 已停用 | 条目还在，但被关掉了：Claude 与 Copilot 的 `disableAllHooks`、Codex 的 `hooks = false`、Antigravity「scyllaui」一项的 `"enabled": false`，或在 Codex、Grok 的 `/hooks` 里逐条停用 | 修复… |
  | 需在 Codex 中信任 | 只有 Codex：条目已写好，Codex 要求您亲自确认一次才执行 | 去信任…（M4b 块 5 起，原为「说明…」）、撤销… |
  | 被组织策略锁定 | 组织策略只允许管理员下发的 Hook，ScyllaUI 不能修复 | 说明… |
  | 读不了配置 | 配置文件格式有误或没有读权限，ScyllaUI 不碰这个文件 | 说明… |
  | 未安装此 Agent | 本机没装这款工具 | 无 |

- 「修复…」「撤销…」先弹出确认框：写明问题、要改的文件与处数、备份位置，下方列出 diff，点确认才写入。写入前把原文件备份为 `<文件名>.scyllaui-bak-<时间>`；确认期间这个文件被别的程序改过时放弃写入，不覆盖别人的改动。「说明…」只说明原因，不改任何东西。
- 撤销只删除 ScyllaUI 写入的条目，您自己的 Hook、其他设置与 Codex 的信任记录都不动。撤销后侧栏不再为这款工具提示；以后修复装回，提示随之恢复。

### 怎么用

- 四款都是「正常」：不用操作。
- 「缺少条目」「条目需要更新」或「已停用」：点「修复…」，看过改动后确认。已经在运行的 CLI 会话不一定马上读到新配置，修复后新开一个会话最稳妥。
- Codex「需在 Codex 中信任」：这一步只能在 Codex 里由您确认，ScyllaUI 不替您写信任记录。M4b 块 5 起有三种更省事的入口，做的是同一件事：「设置 › Agent」那一行的「去信任…」、侧栏 Codex 那一行的「未同步」、修复确认框里的「在 Codex 里打开 /hooks」（修复写入后也会接着提示这一步）。它们会切到正在运行 Codex 的终端（优先您点的那一行、其次当前终端），确认后像粘贴一样在 Codex 输入行填入 `/hooks`、不回车；您按回车打开 Codex 的 Hook 列表（顶部写着「7 hooks need review before they can run」），按 `t` 信任全部待审核的条目（按回车可逐条审核），之后变为「正常」。列表里没有 ScyllaUI 的条目时，退出 Codex 再打开，它启动时会询问是否信任（Hooks need review），三个选项依次是 Review hooks、Trust all and continue、Continue without trusting (hooks won't run)，选「Trust all and continue」；选了最后一项则这次不执行 Hook，侧栏那一行显示「未同步」，之后照上面点它即可。没有正在运行的 Codex 时只说明怎么做，不替您启动 Codex。
- 不想让 ScyllaUI 管某款 CLI，或准备卸载 ScyllaUI：点「撤销…」。

### 其他入口

- **终端行的「未同步」**：正在某个终端里运行的 CLI 状态同步未生效（条目缺失、被停用或 Codex 未信任）时，那一行显示「未同步」，点它走同一套流程（Codex 未信任时去 Codex 里打开 `/hooks`）。在设置里撤销过的工具不提示。没在运行的 CLI 不提示，状态在「设置 › Agent」里看（2026-10-28 起侧栏底部不再显示「状态同步未生效：<工具>」，免得为没在用的 CLI 打扰您）。
- **侧栏提示栏**：M4b 块 6 起，正在运行的 CLI 发来的 Hook 数据有异常时（不认识的事件名、缺事件名或会话 ID、数据无法解析，多半是 CLI 新版本改了格式），侧栏底部提示「状态可能不准：<工具>」，侧栏显示的状态可能不准，点提示栏的「详情…」查看版本与原因（2026-10-30 前写在终端那一行的悬停提示里）；那个 CLI 进程退出后提示随之消失。只是版本不在已验证清单里不提示（原先会提示「未验证版本」）。
  - 右侧的「详情…」：写明每款的版本与原因、影响（只影响侧栏显示状态、通知与「待查看」，Agent 本身和终端不影响）、根源（可能是 CLI 新版本更改了 Hook 数据格式，待 ScyllaUI 版本升级）与可以装回的版本（这款 CLI 最新的已验证版本）。反馈问题时点「报告问题…」（2026-11-02 起，原为「打开日志文件夹」），诊断包会带上日志和各款的版本（`scyllauid.log` 里每次异常记一行「Hook 异常：tool=<工具> terminal=<终端> <原因>」），见第 13 节。
  - 在意的话可以自己装回已验证的版本（ScyllaUI 不替您装）：Claude Code 原生安装用 `claude install <版本>`，npm 安装用 `npm install -g @anthropic-ai/claude-code@<版本>`；Codex（npm 安装）用 `npm install -g @openai/codex@<版本>`；Grok 用 `grok update --version <版本>`；OpenCode（npm 安装）用 `npm install -g opencode-ai@<版本>`；Copilot（npm 安装）用 `npm install -g @github/copilot@<版本>`；Kimi Code 的 `kimi update` 与 Antigravity 的 `agy update` 只能升到最新，暂时没有装回指定版本的办法（以上 2026-10-28 按本机各 CLI 的帮助核对，Antigravity 2026-11-01）。装回后新开的 CLI 进程就不再提示。
- **首次运行引导**：首次打开或主、次版本号变化时，开屏后有两页讲状态同步：「让侧栏知道每个 Agent 在干什么」用图例说明为什么要装，「安装状态同步」列出四款状态，「查看改动并安装…」同样先列出改动、确认后写入（第 2 节）。
- **命令行**：`ScyllaUI.app/Contents/Helpers/scyllaui hooks <子命令>`，规则与 App 相同。`status` 只读查看四款状态；`diff` 只显示要改什么、不写入；`install` 安装或修复四款；`uninstall` 撤销四款。`install` 与 `uninstall` 不再询问，打印改动后直接写入（同样先备份），建议先用 `diff` 看一遍。命令行撤销不记入「不再提示」，侧栏会照常提示；用命令行装好后，App 自动恢复对该工具的提示。
- 也可以手动编辑上述配置文件，但条目要与 ScyllaUI 的写法一致，不建议手改。

## 10. 设置

- 菜单「ScyllaUI › 设置…」（`Cmd+,`）打开设置窗口，顶部按图标分页（0.4 起：「外观」「状态栏」「语言」「通知」「Agent」「数据」「关于」）。设置窗口的深浅与主窗口一致；各分页共用一个尺寸，切换分页时窗口不变（0.4.2 起）。
- **外观**：所有选项选定即作用于所有终端，不必重启。
  - 主题：「默认配置」或下列 10 个配色家族（按各家族在 GitHub 上最受欢迎的仓库的星数排名）：Dracula、Catppuccin、Solarized、Gruvbox、Tomorrow、Tokyo Night、Nord、Kanagawa、Everforest、Nightfox。
  - 深浅：跟随系统（默认，系统切换深浅时终端随之切换）、深色、浅色。Dracula、Nord 只有深色版，固定为深色。
  - 以前从全部主题里选过不在这 10 个里的主题时，列表末尾显示「其他：<名称>」，换选后即被替换。
  - 终端字体：「默认配置」或系统里的等宽字体；字号：「默认配置」或 9—24。在这里改字号时，所有终端都换成新字号，包括用 `Cmd+=` / `Cmd+-` 临时调过的；只改主题或字体时，临时调过的字号保留。
  - 预览：用当前主题的颜色与所选字体显示 4 行样例。字体为「默认配置」时，预览用系统等宽字体代替。
  - 窗口深浅随主题，侧栏与终端一致。
- **状态栏**、**语言**、**通知**：见第 3、2、8 节。
- **Agent**：Claude、Codex、Kimi、Grok、OpenCode、Copilot、Antigravity 各款 CLI 的状态同步（Hook）情况，每款一行，可逐款修复或撤销；各部分含义、七种状态与用法见第 9 节。
- **数据**：
  - 已结束对话的保留：天数 7 / 14 / 30（默认）/ 60 / 90，条数 50 / 100 / 200（默认）/ 500。调小时先告诉您将删除多少条，确认后立即删除；侧栏「最近任务」只显示近 14 天内的 20 条，不随这里变。
  - 「清除记录…」：写明条数、确认后删除 ScyllaUI 库里全部已结束的对话（库文件里也不留原文），正在运行的任务不受影响。
  - 两者都只影响 ScyllaUI 自己的库，CLI 自己的会话记录不受影响。Claude Code 默认 30 天后删除本地会话，保留得更久的记录多半已无法恢复。
  - 启动时恢复上次的终端（0.4.3 起，默认开）：见第 7 节。
  - 写库前脱敏（0.4.3 起）：任务标题、最新提示词与最后回复写进 ScyllaUI 的库之前，常见的密钥写法会换成 `[REDACTED]`：如 `OPENAI_API_KEY=…`、`password: …`、`Bearer …`、`sk-…` / `ghp_…` 等令牌、PEM 私钥、网址里的密码、「密码：…」。侧栏与搜索里看到的也是替换后的文字；只影响 ScyllaUI 自己的库，CLI 自己的会话记录不变。此前已存进库的记录不会补做替换。
- **关于**：版本（构建号 · 构建标识）、后台 scyllauid 是否连接及其构建标识是否与 App 一致、数据目录与日志目录（「在 Finder 中显示」）、更新（「自动检查更新」开关、「检查更新…」与上次检查时间，M4b 块 3）；底部先是一行灰字「ScyllaUI 是自由软件，按 GNU GPL 3.0 或更高版本发布，不提供任何担保。」，下面四个按钮都用系统默认的文本程序打开随包的文件：「开源许可…」（2026-11-07 起，GNU GPL 第 3 版英文原文，取代原先的「许可协议…」）、「使用须知…」（2026-11-07 起）、「隐私说明…」（2026-11-02 起，隐私与数据说明），后两份按界面语言打开中文或英文版，以中文版为准；「第三方许可…」（M4b 块 4 起）是第三方许可清单（终端引擎、字体、配色主题与各项依赖的来源、许可与全文）。

## 11. 卸载

按顺序做，CLI 配置里不会留下 ScyllaUI 的条目：

1. **撤销状态同步**：在「设置 › Agent」里把每款「正常」的工具点「撤销…」，或在终端里运行 `ScyllaUI.app/Contents/Helpers/scyllaui hooks uninstall`（四款一起，不再询问，写入前备份）。装过 Claude 的 statusline 桥的，再运行 `scyllaui statusline-bridge uninstall`。
2. **结束终端与后台**：先让各 AI 答完，或在终端里 `exit`；退出 ScyllaUI，再结束后台进程：macOS 27 及以后在程序坞右键选「Stop Running in Background」，更早的系统在终端里运行 `/Applications/ScyllaUI.app/Contents/Helpers/scyllaui ctl shutdown --force`（第 7 节）。
3. **删除文件**：
   - `ScyllaUI.app`；
   - 数据目录 `~/Library/Application Support/ScyllaUI/`（ScyllaUI 的库、外观覆盖、保留设置）；
   - 日志目录 `~/Library/Logs/ScyllaUI/`；
   - 缓存：`~/Library/Caches/ScyllaUI/`（「报告问题」生成的诊断包）、`~/Library/Caches/dev.scyllaui.app/`、`~/Library/Caches/dev.scyllaui.app.sparkle/`（自动更新下载的安装包）、`~/Library/HTTPStorages/dev.scyllaui.app/`；
   - 偏好设置（界面语言、通知与状态栏开关、欢迎页记录等）：在终端里运行 `defaults delete dev.scyllaui.app`，再删除 `~/Library/Preferences/dev.scyllaui.app.plist`（这条命令只清空设置，文件本身还在）；
   - 修复与撤销时留下的备份：各 CLI 配置文件旁的 `<文件名>.scyllaui-bak-<时间>`，确认不需要后可删除。
4. 可选：在「系统设置 › 隐私与安全性 › 文件与文件夹」和「系统设置 › 通知」里删掉 ScyllaUI 的条目。

没先撤销就删了 App 也不会出错：留在 CLI 配置里的命令只在 ScyllaUI 的终端里运行，找不到 ScyllaUI 时什么都不做。想清掉它们，要手动删除：Claude 的 `~/.claude/settings.json` 与 Codex 的 `~/.codex/hooks.json` 中命令含 `hook --config` 的条目、Kimi 的 `~/.kimi-code/config.toml` 中 `# >>> scyllaui hooks >>>` 到 `# <<< scyllaui hooks <<<` 之间的内容（含这两行）、Grok 的 `~/.grok/hooks/scyllaui.json` 整个文件、OpenCode 的 `~/.config/opencode/plugins/scyllaui.js` 整个文件、Copilot 的 `~/.copilot/hooks/scyllaui.json` 整个文件、Antigravity 的 `~/.gemini/config/hooks.json` 中名为「scyllaui」的那一项（文件里只剩它时可删除整个文件）。

撤销不会删 Codex 自己写的信任记录：您在 Codex 里信任 ScyllaUI 的条目时，Codex 在 `~/.codex/config.toml` 里记下若干 `[hooks.state."…"]` 段（`trusted_hash`）。撤销后它们对应的条目已经不在，Codex 不再使用，留着无害；ScyllaUI 不改这些记录（第 9 节）。

## 12. 已知局限

- Shell 退出码在 ScyllaUI 里总记为 0（macOS 的 `login` 不传递退出码）。
- 换版本后各 AI 的状态先显示「未知」，等下一个事件更新。
- 后台被强制结束（例如「Stop Running in Background」或 `scyllaui ctl shutdown --force`）时，所有终端随之结束；下次打开时按设置恢复（第 7 节）。
- 意外退出时（0.4.3 起）：App 自己退出，系统会弹「意外退出」，点「重新打开」即可，终端都还在后台、重开就接回，重开后 ScyllaUI 会说明上次意外退出的时间（第 13 节）；后台意外退出而 App 开着时，App 会自动拉起新后台，原来跑着 AI 的终端按「启动时恢复上次的终端」开关自动接回 AI（同一段对话 2 分钟内只自动接一次，避免反复出错时来回重试）；接不回的同样说明原因（第 7 节）。
- Codex 连着共享后台运行时（`command codex`、在另起的 `zsh` 或 tmux 里输入 `codex`）状态可能显示「未知」，见第 5 节。

## 13. 报告问题

遇到问题时，用菜单「帮助 › 报告问题…」（2026-11-02 起）；欢迎窗口的最后一页也会介绍怎么报告（每天第一次打开时出现，第 2 节）。「上次意外退出」和「状态可能不准 › 详情…」两个提示框里也有「报告问题…」，从那里打开时，问题描述里已填好提示的标题。

- **它做什么**：在本机生成一个诊断包，列出要附上的文件，您看过、确认后，用您自己的邮件或 GitHub 账号发出。ScyllaUI 不联网，不会自动上传任何内容。
- **怎么填**：写清发生了什么、大约几点（几点几分最重要，日志按时间戳对得上）、怎么复现。
- **诊断包里有什么**：
  - `summary.txt`：App 与后台的版本和构建标识、macOS 版本、界面语言、终端引擎版本、各款 Agent 的状态同步与版本、当前「状态可能不准」的条目、上次意外退出的时间，以及您的描述；
  - `logs/`：后台日志 `scyllauid.log` 和最近 3 天的 App 日志 `app-日期.log`，每个只取最后 2 MB。日志里只有事件、状态与进程号这类信息，不记提示词、回复和密钥；文件里的家目录写成 `~`，目录名仍看得到；
  - `crash/`：30 天内的崩溃报告，即系统为 ScyllaUI 各进程写的 `.ips`，以及终端引擎为本 App 写的最新 3 份（只带版本与本 App 一致的，其他程序的报告不会被带上）。崩溃报告可能带有崩溃瞬间内存里的文字，比如终端里正在显示的内容，所以窗口里可以取消勾选「附上崩溃报告」；
  - 不放 ScyllaUI 的库（里面有提示词和回复）、`workspace.json` 和任何 Agent 的配置。
- **先看再发**：点「在 Finder 中显示」打开诊断包文件夹，可以逐个打开文件查看。诊断包放在 `~/Library/Caches/ScyllaUI/reports/`，7 天后再报告问题时自动清掉。
- **发出**：
  - 「用邮件发送…」（`Cmd+回车`）：在系统「邮件」里新建一封邮件，收件人、主题和正文已填好，诊断包作为附件，您检查后自己点发送。没有设置邮件账户时，改为在 Finder 里显示诊断包，并告诉您收件地址；
  - 「在 GitHub 提交…」：在浏览器里打开预填好标题和正文的新建问题页，同时在 Finder 里显示诊断包，把它拖进页面即可附上。需要您登录自己的 GitHub 账号；问题页是公开的，别人也能看到。
- **只想自己附日志**：按住 Option 打开菜单「ScyllaUI」，「关于 ScyllaUI」会变成「打开日志文件夹」（所有版本都有）；测试版的菜单「ScyllaUI」里另有一项常驻的「打开日志文件夹」；「设置 › 关于」日志目录旁也有「在 Finder 中显示」。同一目录里的终端尺寸日志一般不用附。
- **上次意外退出的提示**（M4b 块 7 起）：ScyllaUI 闪退、被强制结束或断电后，下次打开（开屏关掉之后）会提示「ScyllaUI 上次意外退出（约 <时间>）」，说明终端的去向：后台还保管着终端时「已经接回」；后台也已结束时「终端按设置恢复」（第 7 节）。时间取最后一次运行记录，误差约 1 分钟。点提示里的「报告问题…」，诊断包会带上这个时间。正常退出（`Cmd+Q`、关窗口）、关机、重启与注销都不会出现这个提示。

## 14. 隐私

- 完整的隐私与数据说明在「设置 › 关于 › 隐私说明…」（2026-11-02 起），以下是要点。
- ScyllaUI 的 App 与后台除检查更新外不向互联网发起请求（更新源与安装包在 GitHub，GitHub 会收到 IP 与标准请求信息），不收集、不上传使用数据；内嵌的终端引擎带的崩溃报告组件没有接任何上报通道。例外是 Antigravity、Kimi、Grok 的额度（2026-11-01 用户同意）：后台在这几款一轮结束后，每款最多每 5 分钟另起一次它们自己的程序查询，由它们用自己的登录向各自的服务查询额度，ScyllaUI 不读、不存登录信息，不发送任何内容：Antigravity 执行 `~/.local/bin/agy -p /usage --output-format json`；Kimi 执行 `~/.kimi-code/bin/kimi web --no-open --port 0`，只在本机起一个 Kimi 自己的服务，读它的用量接口后立即结束（它启动时打印的本机访问令牌只在内存里用这一次）；Grok 执行 `~/.grok/bin/grok agent --no-leader stdio`，调它的计费查询后结束。Copilot 的月额度在它自己的会话记录里，不另外查询。
- 您的提示词、AI 回复与任务标题只存在本机 ScyllaUI 的库里（数据目录 `~/Library/Application Support/ScyllaUI/`，写入前替换常见的密钥写法，第 10 节），日志不记这些内容。
- 终端里的 CLI 照常联网，与在其他终端里运行相同，ScyllaUI 不经手它们的网络请求。
- 「帮助 › 报告问题…」生成的诊断包只在您确认后、用您自己的邮件或 GitHub 账号发出，ScyllaUI 不替您上传（第 13 节）。发到 `support@thinkfarlabs.com` 的邮件经 Cloudflare 转发、存于维护者的 Gmail；诊断包问题处理完即删，来往邮件最多保留 12 个月；可随时要求查阅、复制、更正或删除（2026-11-08 起，隐私说明第六、七节）。
